# Changelog

All notable changes to the DOAJ Pre-Assessment plugin. Versions below 1.0 are development builds and release
candidates; 1.0.0.0 is the first production release. Approved criteria are approved by the product owner of this
plugin, not by DOAJ.

## [1.0.0.0] - 2026-10-14 (production release; accepted by the product owner)

Production release 1.0.0.0: approved criteria only; the candidate profile is disabled. See `RELEASE-NOTES.md`.

### Changed

- Version 1.0.0.0, as the release policy requires after product-owner acceptance (2026-10-14) of release candidate
  `v0.10.0.0-rc3`. Release notes, README and the crawler's User-Agent version follow.
- No change to criteria, FQ mappings, evaluation, authorization, persistence, crawling, export or security logic.

## [0.10.0.0] - 2026-10-14 (production release candidate; approved criteria only; independent security audit completed; awaiting product-owner acceptance)

Operational release candidate 2: approved criteria only; the candidate profile is disabled. See `RELEASE-NOTES.md`.

### Added

- Approved criteria dataset 1.0.0 (`classes/rules/data/DoajPaApprovedDataset.inc.php`, generated by
  `tools/apply-approval.py` from the signed approval record), evaluated by the default profile as version 2 of each
  criterion lineage (`DoajPaApprovedRule`). FQ answers for the approved mapping rows only.
- "Pre-assessment, not a DOAJ decision" and "Independent of DOAJ" notices on every page, run and report of the
  approved rule set.

### Fixed (corrected build, 2026-10-14)

- Interface wording describes the approved release:
  - the plugin-list description;
  - Settings: "No configurable settings are available in this release.";
  - the DOAJ Form Guide notice before the first completed assessment, which names the covered questions;
  - the run page of runs made without approved criteria.
- The crawler's User-Agent no longer says "development build".
- No change to authorization, evaluation, persistence, crawling, export or security logic.

### Changed

- Candidate profile switched off (`DoajPaSchema::CANDIDATE_PROFILE_ENABLED = false`): refused on start and on
  continuation; stored candidate runs stay readable.
- Engine `doajpa-checks/2`: D-03-4, D-03-5 and ADR-013 are cited without "PENDING APPROVAL"; no check changed.

## [0.9.0.0] - 2026-10-12 (Stage 05, operational release candidate 1; not accepted for operational use)

Operational release candidate 1; candidate DOAJ criteria are PENDING APPROVAL. See `RELEASE-NOTES.md`.

### Added

- PDF reports embed the DejaVu Sans fonts (unmodified, licence in `classes/reports/fonts/LICENSE-DejaVu.txt`). Unicode
  text is readable and extractable; characters without a glyph are written as [U+XXXX] with a notice. The package
  verifier pins the font files (D09).
- Report quota: at most 30 generated reports per run; further requests get HTTP 429 (Stage 01 F9).
- Normative approval package for the 137 criteria and the FQ mapping (documentation only; nothing approved).

### Fixed

- A passing unapproved-metric check now verify-clears the pages it searched, and a passing endogeny check clears the
  issues it read. Before this fix, page- and issue-level findings could only become "needs verification", never
  "resolved", after a correction. Found by the Stage 05 end-to-end test.
- Inaccurate code documentation (S3-SEC-6, and two report helpers).

## [0.8.0.0] - 2026-10-12 (Stage 04, internal-testing build)

Stage 04 internal-testing build; candidate DOAJ criteria are PENDING APPROVAL. See `RELEASE-NOTES.md`.

### Added

- Before You Apply (Stage 01 F7 item 4, AC-14): corrections of a completed run grouped by the website page to correct,
  with the run's recommended correction and DOAJ clause, the finding and the accountable corrective-action rows. A
  corrective action can be created from a task, prefilled. Unverifiable results are listed as "needs verification".
- Reports (AC-18): HTML, PDF and DOCX, A4, from one report model built from the stored run record (parity), with the
  disclaimer, normative baseline, method, sources not inspected, results, findings, corrections by page, action
  register, Form Guide, limitations, references and attribution. Private storage under `files_dir`. Guarded,
  audited downloads checked against the recorded SHA-256. No third-party library.
- Licence: `LICENSE` (GPL-3.0-or-later) and `NOTICE.md`; an SPDX line in every source file; separate CC BY-SA 4.0
  attribution of the DOAJ-derived dataset, also shown with candidate results.

### Changed

- Candidate engine corrections from the per-criterion acceptance cases (ADR-012 R1.9):
  - abstention is applied consistently ("not applicable", "no contradiction", activity, endogeny);
  - headings and menu labels are not statements;
  - negations inside a claim are respected;
  - conditional "should" clauses give warnings;
  - fee no-charge statements are scoped to the fees they name;
  - HTML/PDF media types are checked;
  - shared article URLs are detected.
- Language-neutral facts from short pages of an English site (ADR-013, PENDING APPROVAL D-03-9): outcome basis
  "neutral", accepted by the outcome guard only for eligible evidence; labelled; never resolves a finding.

### Fixed

- Parallel assessment steps (pre-existing since 0.5.0.0): when several steps saw a finished crawl at the same time, all
  of them evaluated the run concurrently. An intermittent failure of one moved the run to "interrupted" for all, and it
  was never sealed. This was seen once in the Stage 04 regression matrix (PHP 7.3). Evaluation is now serialized by its
  own lock; the other steps report "busy". The security suite runs the six-parallel-steps scenario three times.

## [0.7.0.0] - 2026-10-12 (Stage 03, internal-testing build)

Stage 03 internal-testing build; candidate DOAJ criteria are PENDING APPROVAL. See `RELEASE-NOTES.md`.

### Added

- Deterministic evaluation engine (`classes/rules/`): fact extraction from the stored evidence of one run, 137
  criterion checks for the proposed dataset 0.1.0-draft, modules for editorial endogeny (per issue, uncertain name
  matches abstain), publication-history dates (exact Stage 01 F4 messages), licensing and copyright consistency
  (cross-page contradictions; footer notices kept apart), metrics and indexing claims (Guide-listed metrics only;
  indexing claims inventoried, never judged), and the FQ-01..FQ-20 form-guide builder.
- Candidate assessment profile: chosen per run with an extra confirmation; rule set label
  `candidate-doajpa-criteria-0.1.0-draft`, never an approved rule set; results, findings and form answers are
  labelled "Candidate criteria - PENDING APPROVAL" and "Not a DOAJ assessment result". The default profile is
  unchanged (approved criteria only: none).
- Corrective recommendations with the DOAJ clause on every fail, warning and contradiction; the verified quotes and
  evidence pages a result relies on are stored with the result.

### Changed

- ADR-011: page language is identified from the main content region (`role="main"`, `<main>`,
  `pkp_structure_main`, ...), without navigation, breadcrumbs, sidebars or footers; too little text stays
  undetermined. HTML extraction `doajpa-html/2` stores three evidence rows per page (main content, page structure
  and metadata, whole-page text). Fingerprints of earlier runs therefore change once.
- Outcome guard (ADR-010 R1.8): a pass may rest on a declared absence or observation basis only when it cites
  searched pages that are all verified English; otherwise a verbatim quote is still required.

### Not included

- Approval of any criterion or of the FQ mapping (decisions D-03-1 to D-03-5 PENDING APPROVAL), external registry
  lookups (ISSN Portal, DOI resolution), reports (Stage 04), Before You Apply.

## [0.6.0.0] - 2026-10-10 (Stage 02.08, development pre-release)

Stage 02 framework; normative DOAJ assessment rules are not yet complete. See `RELEASE-NOTES.md`.

### Added

- Reproducible installation archive: built from a git commit with fixed ordering, owner, modes and times, and an
  in-archive `MANIFEST.sha256`; an archive verifier for structure, metadata, integrity and absence of development code.
- `RELEASE-NOTES.md` with the list of features that are not available.
- README: installation, activation, deactivation, upgrade, rollback, uninstall, reinstall and recovery for OJS 3.3.0-23;
  the English-only warning at the top.

### Fixed

- After a database restore (rollback), a new run could receive the ID of a discarded run whose private crawl files
  were still present; the crawl then refused to start and the run could not be completed. The private crawl state is
  now bound to its run: stale files are moved aside (never deleted) and recorded in the audit log, and a step refuses
  a state that belongs to another run or is ahead of the stored records. Crawl states written by 0.5.0.0 are accepted
  for their own runs.

## [0.5.0.0] - 2026-10-10 (Stage 02.07, development build)

### Added

- Assessments can be started from New Assessment by a Journal Manager, with the English-only confirmation
  required (and recorded) for every run. Runs advance in bounded, CSRF-protected steps (start, continue, resume,
  cancel), with optimistic locking for resume and cancel, and one active run per journal.
- Assessment framework: versioned criterion rule interface, an outcome check that only ever downgrades
  (quotes must appear verbatim in stored evidence; a pass needs verified-English evidence; failed rules give
  "unverifiable"), evaluation and sealing in one transaction, and reuse of a previous result only when the
  rule's inputs are unchanged (fingerprints), re-checked against the new evidence.
- No DOAJ rules: every criterion module is recorded and shown as NOT IMPLEMENTED; FQ-01 to FQ-20 are stored as
  "Not yet assessed"; the DOAJ Form Guide lists them.
- Run page: progress, interruption reason, coverage and gaps (including pages whose language is not verified
  as English), changes since the previous run, and the framework summary.
- Interrupted runs (for example an unwritable private directory) can be resumed without duplicate records.

### Changed

- Pages whose language the advisory check cannot establish are marked
  `language_undetermined (advisory heuristic; not verified English)` and counted in the coverage summary.
- The crawl time limit counts crawling time only, so a resumed run keeps its remaining time.
- A failure to create the crawl lock file is an error (the run is interrupted) instead of a "busy" answer.

### Documentation

- Poppler `pdftotext` is an optional external prerequisite (not bundled); README describes its unavailable and
  error behaviour.

## [0.4.0.0] - 2026-10-09 (Stage 02.06, development build)

### Added

- Public website crawler for one journal (no user interface yet): starts from the journal homepage as OJS
  routes it, stays on the same host, port and journal path, skips OJS backend and dynamic paths, honours
  robots.txt, and applies limits on pages, issues, articles, files, depth, size and time.
- SSRF protection: only http/https; strict host syntax; every resolved address must be public; the vetted
  address is pinned for the connection; every redirect hop is re-checked; no proxy, cookies or credentials;
  size caps after decompression. The crawler refuses to run when OJS is configured with an HTTP proxy.
- HTML text and link extraction (scripts never executed or followed) and PDF text extraction with page
  markers through the server's `pdftotext`, with explicit statuses for missing, inaccessible, unreadable,
  scanned, encrypted, oversized and non-English content.
- Results are stored through the existing services with URL, final URL, HTTP status, media type, SHA-256,
  UTC time and extraction version; a coverage summary is stored on the run and a full manifest privately.

### Security

- A development-only exception for private test addresses exists only in unpackaged test code and needs an
  exact switch value and exact host:port=ip entries; it is never part of this package.

## [0.3.0.0] - 2026-10-09 (Stage 02.05, development build)

### Added

- Backend views (Stage 01 F8 navigation): Overview, New Assessment, Criteria & Findings, finding detail,
  Evidence, DOAJ Form Guide, Before You Apply, Corrective Actions (create and edit), Assessment History,
  run detail, run comparison, Reports and Settings (including the audit log).
- Historical statuses are read from each run's own observations; comparisons flag different criterion versions.
- Every run is labelled "Not a DOAJ assessment result" while no approved DOAJ rule set is installed.
- Corrective-action edits use optimistic locking: a concurrent change gives HTTP 409 and saves nothing.
- Backend menu entry, shown only to users the plugin authorizes.
- Stylesheet: text-labelled badges, visible focus, layouts that fit narrow screens.

### Not included

- Running assessments, report generation and downloads, the Form Guide and Before You Apply content.
  These pages say so and show nothing generated.

## [0.2.0.0] - 2026-10-09 (Stage 02.04, development build)

### Added

- Plugin-owned schema (13 `doaj_` tables) with an idempotent migration run by `install.xml`, `upgrade.xml`
  and the OJS install/upgrade path. Journal isolation is enforced by composite foreign keys.
- Service layer for assessment runs, crawl resources, evidence, criterion results, form answers, findings
  with stable IDs, append-only observations and transitions, corrective actions, report-export metadata,
  acknowledgements and audit events.
- Completed runs are sealed with a SHA-256 snapshot digest and are never modified.
- A per-run English-only acknowledgement is required to create a run. The first-use acknowledgement and
  authenticated access denials are recorded in the audit log.
- Plugin requests answer HTTP 503 with remediation text when the schema is missing (manual-copy installs).

### Not included

- Crawling, DOAJ rules, findings from real assessments and any user interface for history. The history
  engine is exercised only by test fixtures.

## [0.1.1.0] - 2026-10-09 (Stage 02.03, development build)

### Security

- Deny every OJS "Login as" (impersonated) session. Before this fix, a Journal editor or a non-root site
  administrator could reach the plugin by using "Login as" on a default Journal manager (ADR-002 R1.3).

### Fixed

- `acknowledge` rejects non-string `warningSha256` input instead of casting it.
- Plugin pages mark their content `lang="en"`, so it stays correctly labelled under a non-English interface locale.

## [0.1.0.0] - 2026-10-09 (Stage 02.02, development build)

### Added

- Generic plugin bootstrap for OJS 3.3.0-23: `index.php`, `version.xml`, `DoajPreAssessmentPlugin`.
- Backend-only page `/{journal}/doajPreAssessment`, routed only while the plugin is enabled for that journal.
- Central authorization guard: user ID 1 with a verified site-administrator role, or a member of the
  journal's default "Journal manager" group. Everyone else receives HTTP 403 with no data.
- Op allow-list (404 for any other handler method), HTTP method checks (405) and CSRF on POST.
- Mandatory English-only first-use acknowledgement per journal (exact Stage 01 F1 text), bound to the
  SHA-256 of the warning text.
- English-only warning in the plugin description and in a notification after enabling.
- English locale file registered for every interface language.

### Not included

- Assessment, crawling, findings, history, reports and DOAJ rules. These belong to later stages.
